# 案件統計｜報告輸出格式決策紀錄

決策日期：2026-11-05  
適用範圍：案件統計－版型1（圖表）與版型2（月報）  
討論基準：封存(4).zip

## 目前定案

兩個版型都保留「輸出格式」下拉選單，依序提供「網頁報告、PDF、Word」，預設為網頁報告。這一階段用來讓客戶確認介面，選擇格式只會更新選取狀態。現階段只確認這項設計方向。本次交付為決策紀錄，既有頁面的實作狀態以專案原始碼為準。

## 為什麼先做到這裡

這是政府專案，團隊希望控制第三方依賴，讓交接與後續維護簡單。Word 的實際需求是下載一份含文字和表格的標準 .docx；頁碼、複雜排版與套用正式範本均不在目前需求內。因此先確認客戶要的介面，再決定正式輸出的實作方式。

## 討論過的方案

| 方案 | 當時的考量 | 本次決定 |
| --- | --- | --- |
| JSZip 打包 .docx | 前端組出文件內容，JSZip 負責封裝。必須維護底層文件格式並管理套件版本。 | 暫不採用 |
| docx.js 直接建立文件 | 能直接建立段落與表格。先前試作的 9.6.1 瀏覽器版本內含 JSZip 3.10.1，仍有第三方依賴。 | 暫不採用 |
| 以專案內程式產生固定格式 .docx | 可減少外部依賴，但團隊要負責封裝正確性與 Word 相容性。 | 列為日後選項，尚未定案 |
| 僅保留原生 HTML 下拉選單 | 足以展示三種輸出選項，也無須為選單新增套件。 | 本次採用 |

## 交付與後續

本次僅交付這份 Markdown。先前的 stats-formats-update.zip 和 direct-word-update.zip 保留為試作紀錄，暫不匯入專案。

若客戶日後確認要開發 Word 下載，驗收以這三點為準：

1. 下載真正的 .docx，能以 Microsoft Word 開啟，且沒有修復提示。
2. 報告含標題、選定月份與科別，以及對應統計表。
3. 中文、數字及示範資料標示均與畫面一致。

網頁報告與 PDF 的實際輸出行為，待客戶確認後另行開發。
